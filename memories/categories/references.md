- **R-007** [2026-11-26] #browser #llm #python — Skyvern (AI form filling, AGPL, pip `skyvern[server]` 1.0.58) runs fully local without Docker/Postgres: `Skyvern.local(use_in_memory_db=True)` + `launch_local_browser()` + `page.agent.run_task(prompt)`; text-only (HTML element tree, no screenshots) with `LLM_CONFIG_SUPPORT_VISION=false`.
  - How: own venv (`uv venv .venv-skyvern --python 3.12`, `uv pip install … "skyvern[server]"`, `playwright install chromium`). Settings are read from env and `./.env` at import time: set them before `import skyvern` and `chdir` away from folders whose `.env` holds other secrets. OpenRouter: `ENABLE_OPENROUTER=true OPENROUTER_API_KEY OPENROUTER_MODEL LLM_KEY=OPENROUTER SECONDARY_LLM_KEY=OPENROUTER`. Ollama: `ENABLE_OLLAMA=true OLLAMA_SERVER_URL OLLAMA_MODEL OLLAMA_SUPPORTS_VISION LLM_KEY=OLLAMA` (see I-036). Set `SKYVERN_TELEMETRY=false`.
  - Gotchas: AI `page.upload_file(prompt=…)` crashed on the in-memory DB (`Could not refresh instance WorkflowRunBlockModel`); do uploads with raw Playwright `page.page.set_input_files(sel, path)`. Type native text/email/tel/url/textarea fields yourself with Playwright `fill()` and give the agent only the choice fields (dropdowns, radios, checkboxes) as question → answer pairs keyed by label text. A "type character for character" prompt did not stop it reformatting `+44 7700 900123` as `07700 900123`. The hybrid scored 17/17 in 70 s, against 16/17 in 158 s all-AI. Labels are best collected with a no-AI DOM scan (label[for], closest label, aria-label, else the nearest ancestor `<label>`). Treat a checkbox/radio group as one question, but only when its fieldset holds just that group (a whole-form "Questions" fieldset would mislabel it); otherwise group by `name` and use the preceding sibling text. Skip `g-recaptcha-response`/csrf/token fields and invisible inputs, except file, checkbox and radio. On Ashby, Yes/No questions are buttons over a hidden checkbox. Never auto-submit real ATS forms (reCAPTCHA, and the candidate must review): fill, then leave the browser open.
  - Evidence: mock ATS form, 13/14 fields exact + consent + CV upload in 152 s with `nvidia/nemotron-3-ultra-550b-a55b:free`, HTML only (AutoJobSearch `formtest/`, 2026-11-26).
- **R-006** [2026-11-26] #json — Keyless job-posting APIs: full text from Greenhouse/Ashby/Lever public APIs, plus Remotive/Jobicy/RemoteOK feeds. ATS postings almost never include a recruiter e-mail.
  - How: Greenhouse `https://boards-api.greenhouse.io/v1/boards/{org}/jobs/{id}` → `content` (HTML, double-escaped). Ashby `https://api.ashbyhq.com/posting-api/job-board/{org}?includeCompensation=true` → find `jobs[].id`, use `descriptionPlain`. Lever `https://api.lever.co/v0/postings/{org}/{id}`. `{org}`/`{id}` come from the job-board URL path. Remotive `remotive.com/api/remote-jobs?search=…&limit=50`; Jobicy `jobicy.com/api/v2/remote-jobs?count=50&tag=security` (salaryMin/Max/Currency/Period); RemoteOK `remoteok.com/api?tag=security` returned 0 jobs (2026-11-26). All ask for attribution/link-back. Jobicy tags substring-match: `tag=soc` returned social-media, payroll and "associate" jobs, so avoid short tags and still filter titles locally.
  - Check every scraped contact address in context before e-mailing it: `jobs@zapier.com` on a posting was only the disability-accommodation contact ("If reasonable accommodations are needed… please contact"), and `recruiting@zapier.com` on the careers page was only for reporting recruitment scams. Neither is an application inbox. Neither were `hr@nebius.com` (HR questions and follow-ups) nor `contact@alan.com` (customer support, from JSON-LD `Organization.email`): all 3 "found" recruiter e-mails were wrong. Rule that works: require **positive evidence**. Accept an address only if a mention says to send CVs or applications to it (`send|email|submit … (cv|resume|application)`, `apply by e-mail`, `applications … to`), and reject mentions near `accommodat|disabilit|eeo|scam|fraud|suspicious|phishing`. This passed 9/9 real and synthetic cases. Also check location eligibility on the ATS (alan: "Anywhere in France, Belgium, Spain" = not open to UK). Remote jobs mirrored on boards (Jobicy) often have the real ATS posting on Ashby/Greenhouse/Lever. Look it up via the Ashby API (`jobs[].jobUrl`, `location` + `secondaryLocations`; e.g. NAMER + EMEA = UK eligible) and apply at `<jobUrl>/application`.
  - Latvia: cv.lv JSON `GET https://cv.lv/api/v1/vacancies-service/search?limit=100&offset=0&keywords[]=<q>&sorting=RELEVANCE` (no key; brackets must be literal: requests `params=[("keywords[]", q)]`, or `curl -g`; URL-encoded `%5B0%5D` is silently ignored). Fields: `positionTitle, employerName, remoteWorkType (FULLY_REMOTE|HYBRID|ON_SITE), salaryFrom/To (EUR gross per month; hourlySalary flag), publishDate, keywords, skills`; vacancy URL `https://cv.lv/en/vacancy/{id}`. Keyword search is loose (matches company names), and the `remoteWorkTypes[]` filter returned 0, so filter locally. Search Latvian terms too (`kiberdrošība`, `sistēmu administrators`); `drošība` also means physical safety (fire/workplace/process), so exclude those titles. On 2026-11-26 only 8 of 495 IT jobs were fully remote, at €2–6k/month.
  - Why: across 146 remote security jobs, only 3 companies had a public recruiting e-mail (on the posting or `/careers`), so plan an "apply via ATS form" path. CV-fit keyword scoring was inflated by generic terms (logs, Windows, APIs) until core skills got most of the weight.
  - Use when: building any job search or auto-apply tool (AutoJobSearch-Application, 2026-11-26).
- **R-005** [2026-11-25] #json — Keyless vulnerability data APIs (all worked from this machine 2026-11-25): CISA KEV JSON, NIST NVD CVE API 2.0, CVE.org CVE Services, FIRST EPSS.
  - How: KEV `https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json` (~1.9 MB, ETag; mirror `raw.githubusercontent.com/cisagov/kev-data/develop/…`). NVD `https://services.nvd.nist.gov/rest/json/cves/2.0?hasKev` = every KEV CVE in one ~20 MB page (`resultsPerPage=2000`); `pubStartDate=…Z&pubEndDate=…Z&cvssV3Severity=CRITICAL` (window ≤ 120 days); no key = 5 requests/30 s (sleep 6.5 s), header `apiKey` for 50. About half of new CVEs have no `configurations` (CPE) yet: get vendor/product from `https://cveawg.mitre.org/api/cve/<id>` → `containers.cna.affected[]`. EPSS `https://api.first.org/data/v1/epss?cve=A,B,…` (≤ 100 per call). CVSS choice: NVD `Primary` before CNA `Secondary`; keep the source for display.
  - CVE.org record for any CVE (~1 s each, no key; 4 parallel workers were fine for ~320 look-ups): CVSS in `containers.cna.metrics[].cvssV3_1|cvssV4_0|cvssV3_0`, else CISA's ADP (`containers.adp[]` with `providerMetadata.shortName == "CISA-ADP"`, Vulnrichment) `metrics[].cvssV3_1`; CWE in `cna.problemTypes[].descriptions[].cweId`; ~5% of IDs named in feeds return 404 (reserved/rejected). Good for turning CVE ids mentioned in feeds into scored, product-attributed records without NVD's rate limit.
  - Use when: building any CVE/exploitation dashboard (CVE_Intel v0.10). 42 working security RSS feeds by group are listed in `C:\_web_apps_2025\CVE_Intel\config\sources.yaml`.
