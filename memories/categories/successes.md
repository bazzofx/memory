# Successes — what worked well and should be repeated

Load when: choosing an approach for something that was hard before. Multi-step reusable workflows belong in `procedures.md` instead.
Format: `- [YYYY-MM-DD] <approach>. Why: <evidence it worked>.` Newest first.

- [2026-11-24] To verify a packaged Electron app without desktop control, launch the `.exe` with `--remote-debugging-port=9333`, then use a Node script (global `fetch` + `WebSocket`) to read `http://127.0.0.1:9333/json` and send CDP `Runtime.evaluate` (page text, `fetch` to its APIs) and `Page.captureScreenshot`. Close it with `window.close()` and check `tasklist` for leftover processes. Before launching, check that no copy is already running, for example one the user opened (`Get-CimInstance Win32_Process` shows its path and start time). With a single-instance lock, a second launch hands over to the running copy and exits, so the debug port never opens. Don't kill the user's copy. A portable build also unpacks itself first, so wait longer than 60 s for it. Why: this verified the Kairo portable exe end to end (UI rendered, the bundled Luci started, nothing left running after close). Script: the Kairo session's scratchpad `cdp-luci.mjs` pattern.
- [2026-11-24] Local text to speech: choose the engine by measuring **startup time** and **time to the first sentence** on the target machine. Piper (`piper-tts`, ONNX, CPU) won over Kokoro. Stream sentence by sentence (a producer thread fills a small queue while the current sentence plays), and stop with a generation counter. Why, on a GTX 1070 PC: Piper started in about 5 s with the first sentence in about 1 s on the CPU, and stopped within 0.2 s. Kokoro took about 35 s to start and 3–5 s before the first word on the CPU (0.3 s on the GPU, using 840 MB). Code and API notes: `C:\_web_apps_2025\kairo\docs\voice-tts-handoff.md`.
- [2026-11-24] When an LLM acts on user data, use "model proposes, code decides":
  - Send the items as compact lines with short refs.
  - Force a JSON schema reply (`{say, actions[]}`, Ollama `format` = schema, temperature 0, `think: false`).
  - Have the model copy date words while the app's own code resolves them.
  - Validate every action with the normal command contract, and drop unknown refs and impossible changes.
  - Ask the user to confirm before applying.

  Why: in Kairo/Luci it worked end to end (answers, a bulk reschedule, a breakdown into steps, cancel), and no invalid change reached the store.
- [2026-11-23] To find *which layer* is mangling a command, compare what the transcript recorded as sent (`~/.claude/projects/<proj>/<session>.jsonl` → `"command"`) with the output's bytes (`od -An -tx1`, not `od -c` or `echo`), using a tiny harmless probe. Then vary the quoting (`'…'`, `<<'EOF'`, `"…"`) one at a time. Why: this showed the Bash tool, not Bash, halves `\\`, which was the real cause behind failures blamed on heredoc quoting. Evidence: `dreams/experiments/DREAM-001/run-20261123-01/report.md`.
- [2026-11-23] Before building a warning hook or checker, measure its trigger against real past calls taken from the transcripts. Report recall on hand-labelled failures and the warning rate on calls that succeeded, and compare with the naive trigger. Why: the dream's proposed trigger would have warned on 23% of good calls; the tested version caught 4/4 real failures and warned on 4%. The measurement also turned up 2 silent failures (exit 0, invalid JSON) that no error scan had found.
- [2026-11-23] Keep shell test cases as one file per case, written verbatim with the Write tool, and generate hook stdin with `JSON.stringify` in a runner script. Never hand-escape commands inside a JSON fixture. Why: it avoided another escaping layer while testing escaping bugs; 22 cases plus 6 robustness checks ran reproducibly on the first try.
