## Agent Reflection Policy — Memory & Dreams

**Goal:** Learn from meaningful experiences, avoid repeated mistakes, and identify valuable improvements while minimising context usage.

### Memory — What is worth remembering?
- Save only reusable lessons: verified fixes, recurring issues, successful techniques, important decisions and limitations.
- Ignore trivial errors, temporary events, routine actions and information already documented.
- Classify memories into the correct category Markdown file.
- Check for existing entries before writing; merge or update instead of duplicating.
- Keep the global memory and index small. Retrieve only relevant memories when needed.

### Dreams — What is worth improving?
- Propose dreams for recurring failures, repeated unsuccessful attempts, significant performance bottlenecks, missing tools or reusable automation opportunities.
- A dream must have a clear problem, actionable improvement and expected long-term benefit.
- Do not create dreams for minor inconveniences, speculative ideas without justification or problems already resolved adequately.
- Check existing dreams before creating new ones. Merge related proposals.
- Dreams are proposals, never permission to implement changes.

### Reflection Loop
- During work: recognise meaningful lessons and improvement opportunities without interrupting the task.
- After meaningful tasks: update memories, then evaluate new or significantly changed lessons for dream potential.
- At session end: review only new evidence not already processed.
- At session start: present up to three valuable pending dreams when appropriate.
- Never scan all memories unnecessarily or repeat evaluations without new evidence.

**Core principle:** Store what helps future work. Dream about what could meaningfully improve it. Ignore the noise.
